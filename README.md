# Caraxes

A Codex plugin for a test-driven development workflow.

## Status

Version 0.1.0 contains a greeting skill to verify plugin packaging and installation.
The TDD workflow is not implemented yet.

## Project structure

```text
caraxes/
├── AGENTS.md
├── .agents/plugins/marketplace.json
└── plugins/caraxes/
    ├── .codex-plugin/plugin.json
    └── skills/caraxes-greet/SKILL.md
```

- `AGENTS.md` defines repository conventions, including English project artifacts.
- `marketplace.json` is the repository's plugin catalog, named `personal` by the
  official scaffold. Its `./plugins/caraxes` source is relative to the repository
  root, not to the catalog file.
- `plugin.json` identifies Caraxes and points to its skills directory.
- `SKILL.md` contains discovery metadata and greeting instructions.

This project uses the supported Codex compatibility layout generated by
`plugin-creator`. The official documentation also describes a portable root
`plugin.json` format; the two layouts should not be mixed casually.

## Install locally

Run these commands from the repository root with Codex CLI installed:

```bash
codex plugin marketplace add "$PWD"
codex plugin add caraxes@personal --json
codex plugin list --marketplace personal --json
```

The marketplace command registers this local checkout. The install command updates
Codex's local plugin cache and configuration; it does not publish the plugin.
The repository catalog uses the scaffold's default name `personal`. If you already
have another marketplace with that name, resolve the naming conflict before adding
this one.

## Smoke test

After installation, start a new Codex conversation so it loads the installed skill.
Select `caraxes-greet` from the skill picker and send:

```text
Use $caraxes-greet to greet me. My name is Alex.
```

Expected behavior: a short English greeting that mentions Alex and introduces
Caraxes. Inspect the skill-loading activity to confirm that Codex actually reads
the installed `caraxes-greet/SKILL.md`; a generic greeting alone is not evidence of
plugin loading.

Also try a greeting without a name: it should not invent one. An unrelated request,
such as explaining a Git diff, should not select this greeting skill automatically.

## Validation

Validated with Codex CLI 0.155.1:

- The bundled `plugin-creator/scripts/validate_plugin.py` accepted the plugin.
- The bundled `skill-creator/scripts/quick_validate.py` accepted the skill.
- `codex plugin add` installed Caraxes 0.1.0 successfully.
- `codex plugin list` reported `installed: true` and `enabled: true`.

Fresh-conversation behavioral testing is still pending. Keep this feature on its
issue branch until that smoke test passes; installation alone does not prove the
skill was loaded or followed.
